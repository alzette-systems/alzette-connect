# Alzette Connect 0.3.14

Connect can sign in again after a saved session expires or becomes unusable,
without requiring sign-out first. Explicit sign-in falls back to the system
browser when the identity service rejects a saved refresh credential. Startup
still waits for an explicit action before opening the browser in that case.

Temporary network and identity-service failures preserve the saved login.
Background status refresh can recover when the service returns. Disconnecting
an application preserves a pending sign-in requirement, and reconnect cannot
replace an active application session.

Nine regression tests cover expired credentials, offline reconnect, service
recovery, cancellation and concurrent actions. The rebuilt native macOS app
also recovered from a rejected refresh credential against a local identity
fixture without signing out first.

macOS packages use the existing Developer ID signing, notarization and stapling
workflow. This release does not change the updater implementation, callback
port-conflict guidance, or ChatGPT's compatible-function-tool limit.
